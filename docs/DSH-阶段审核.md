# 阶段自检与自动继续

S1–S5 各自保留一个后端审核记录。每轮重新检查真实保存的产物及当前计划绑定，检查通过后等待用户 60 秒，共三轮。三次等待完成、产物检查通过且没有待处理用户指令时，后端记为 `elapsed`，Host 唤醒同一个会话继续生产。正常情况下等待共 180 秒，检查耗时另计。

用户可以在工作台提前继续，仍需通过产物检查。明确暂停、未处理指令、自检失败都不会因超时放行。自检失败返回具体原因，修复后使用 `benchforge_stage_review(action=retry)`。`acknowledge` 只处理已应用的用户指令，恢复原有轮次，不代表模型能够自行提前批准。

普通执行绑定、同角色的一一改名、缩小几何例外、软摘要及其修订记录沿用原审核和已完成等待。题量、测量条件、硬要求、标注与原生采集要求、评分、物理假设、空间关系、扩大几何例外等变更仍建立新审核，避免把降级伪装成修补。

## 代码边界

| 位置 | 职责 |
| --- | --- |
| `src/storage/review_progress.py` | 三轮状态转换，不读取业务产物 |
| `src/storage/stage_reviews.py` | SQLite 持久化、版本迁移、检查结果的条件提交 |
| `src/pipelines/benchmark/execution/review_checks.py` | 验证当前计划、可执行合同、各阶段实际完成回执及采集源版本 |
| `src/pipelines/benchmark/execution/review_service.py` | 工具、执行器、网页和定时器共用的后端入口 |
| `src/dsh/host/stage_reviews.mjs` | 通过公开 subprocess 服务调用后端，随插件卸载终止调用 |
| `src/dsh/production/lifecycle.mjs` | 按会话安排定时器，通过公开 `steer` / `followup` 续跑，去重并保留用户取消 |
| `src/dsh/production/reviews.mjs`、`review_policy.mjs` | 同步只读快照和公开工具守卫，不凭浏览器或 JS 时钟放行 |
| `src/ui/workbench/components/products.js` | 展示后端轮次、检查结果、倒计时和用户控制 |

符合 [DSH 预设规范](DSH-预设能力与编写规范.md)：领域状态独立持久化，Host 使用公开服务和生命周期，Client 只展示并提交用户操作。无需修改 DSH 核心或 Isaac Sim 接口。

## 并发与恢复

检查使用每个审核独立的操作系统锁，SQLite 仅在读写记录时持有短事务。多个工具、浏览器或 Host 同时观察不会增加轮数。检查期间到达的暂停、指令、计划修订或新阶段使旧检查结果失效。进程退出释放检查锁；重启读取已保存轮次。停机期间不能伪造检查，也不倒填尚未执行的等待。

旧的已放行记录保留原结果；旧的未完成审核在第一次后端访问时迁移，从真实自检开始，不伪造历史检查次数。发布前备份审核数据库、会话存储和本地配置。浏览器关闭或模型结束本轮后，Host 定时器仍可推进当前审核。

## 采集完成后的续行

采集提交工具返回 `submitted`、`submission_accepted=true` 和 `scene_acceptance=pending`，只表示请求已受理。Host 自动登记按会话和运行编号持久化的后台观察；不再依赖模型记得调用 `benchforge_wait(background=true)`。工具返回之后才到达的成功或失败结果，通过标准用户消息及公开 `steer` / `followup` 唤醒原会话。登记失败仍返回已提交作业的身份，恢复跟踪时不得重复提交采集。

`src/dsh/tools/scene/capture/capture_runtime.mjs` 持有 `storageDomain`、服务客户端及插件生命周期；`continuation.mjs` 负责观察、重试交接、结果去重与续行；`continuation_state.mjs` 从标准 Native/PTC 工具事件恢复归属。重载恢复未完成观察，已消费的通知不重放；用户暂停、取消、新任务和已完成流水线不会被旧采集通知重新驱动。多个运行独立观察，同一运行的重试切换代次并终止旧的状态查询，不取消实际服务作业。

采集验收失败必须读取实际缺项，保留硬要求及可辨识资产，修复完整程序并重新采集。只写“下一步修复”不能结束生产义务。采集成功后仍须继续实际流水线或进入对应阶段审核。确有外部阻塞，或同一场景连续两轮失败项没有改善时，使用 `benchforge_scene_blocker` 保存所属服务作业的证据、具体原因和缺失条件；这不会将失败场景改为通过。连续三次尝试收尾且没有新增工具活动时，Host 记录执行受阻，停止空转并要求明确报告未完成。

后台状态查询最多连续重试三次，再通知原会话恢复跟踪，避免网络故障触发无限重试。工作台只读取 `benchforgeProduction` 投影，显示等待采集、需要修复、继续生产、跟踪异常或受阻；浏览器不判断验收、不持有续行计时器。回归测试包括“对话先结束、失败后到达”、重载恢复、并发重试、通知去重、取消和新任务隔离。
